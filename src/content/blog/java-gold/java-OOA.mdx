# 啥是Java OOA

OOA就是面向对象设计和编程，先来看考纲，Java Gold主要考察以下几个部分：

- 声明并实例化 Java 对象（包括嵌套类对象），并解释对象生命周期（包括创建、引用重新赋值和垃圾回收）。
- 创建类和记录类 (`record`)，定义并使用实例字段和静态字段、方法、构造函数，以及实例初始化块和静态初始化块。
- 实现方法重载（Overloading），包括可变参数（var-arg）方法。
- 理解变量作用域，使用局部变量类型推断 (`var`)，应用封装原则，并使对象不可变（Immutable）。
- 实现继承，包括抽象类 (`abstract`) 和密封类 (`sealed`)。重写 (`Override`) 方法，包括 `Object` 类的方法。实现多态，区分对象类型与引用类型。执行类型转换，使用 `instanceof` 运算符和模式匹配（Pattern Matching）来识别对象类型。
- 创建并使用接口，识别函数式接口，并利用接口的 `private`、`static` 和 `default` 方法。
- 创建并使用包含字段、方法和构造函数的枚举 (`enum`)。

但实际上这里有很多司马的细节是平时不会用的，考试会出很司马的写法来考细节，我们概括几个方面。

## 初始化和各种代码块

假如我们初始化一个类，首先要进行类加载，然后再创建实例。也就说，首先JVM把“图纸”实例化，然后根据图纸创建一个实体。

那么问题就在于什么能触发类加载，这是关键的：

- new 一个对象时
- 访问类的 static 变量 (非 Final)
- 调用类的 static 方法
- 使用反射 (Reflection)
- 初始化子类时，父类会被“连坐”
- 虚拟机启动时的“启动类” (Main Class)

但是当混合了静态代码块和实例代码块（虽然这些b用没有）时，会觉得混乱，看个例子：

```java title="Parent and Child"
class Parent {
    // 1. 父类静态
    static { System.out.println("A: Parent Static"); }
    
    // 3. 父类实例
    { System.out.println("B: Parent Instance"); }
    
    // 4. 父类构造
    Parent() { System.out.println("C: Parent Constructor"); }
}

class Child extends Parent {
    // 2. 子类静态
    static { System.out.println("D: Child Static"); }
    
    // 5. 子类实例
    { System.out.println("E: Child Instance"); }
    
    // 6. 子类构造
    Child() { System.out.println("F: Child Constructor"); }
}

public class Test {
    public static void main(String[] args) {
        System.out.println("--- 第一次 new ---");
        new Child();
        
        System.out.println("\n--- 第二次 new ---");
        new Child();
    }
}
```

静态块会在类加载阶段就执行，想象一下，我们必须先将“图纸”看一遍。所以首先是父类的类加载，然后是子类的类加载。

接着`实例化之前` 会执行实例代码块，然后再实例化，这两个步骤对于一个类是紧接着完成的。在 JVM 眼里，实例代码块的代码会被“拷贝”到构造函数的 super() 之后、构造函数代码体之前执行。

那么其实就是父类实例代码块-父类实例化，然后子类同理。

所以完整的输出就是：

```
--- 第一次 new ---

A: Parent Static (先加载父类)

D: Child Static (再加载子类)

B: Parent Instance (开始初始化父类对象)

C: Parent Constructor

E: Child Instance (父类好了，开始初始化子类对象)

F: Child Constructor

--- 第二次 new --- (注意：静态块不再执行！)

B: Parent Instance

C: Parent Constructor

E: Child Instance

F: Child Constructor
```

还有需要注意的是，假如我们想对于一个类连续创建两个实例化对象，其中的静态代码块会执行两次吗？显然是不会的，因为类加载只会在第一次new对象时才执行，就算你使用反射，只要不用不同的ClassLoader，是不会重新加载这个类的。

下面这个代码可以强制触发二次类加载：

```java title="二次类加载"
import java.net.URL;
import java.net.URLClassLoader;

class MyTest {
    // 这是一个静态块，正常情况下只打印一次
    static {
        System.out.println("🔥 静态块执行了！类被加载了！");
    }
}

public class DoubleLoadTest {
    public static void main(String[] args) throws Exception {
        // 1. 获取当前类路径
        URL url = DoubleLoadTest.class.getProtectionDomain().getCodeSource().getLocation();

        // 2. 创建【加载器 A】
        ClassLoader loaderA = new URLClassLoader(new URL[]{url}, null); // parent设为null以强制自己加载
        Class<?> classA = loaderA.loadClass("MyTest");
        // 触发初始化
        classA.newInstance(); 

        System.out.println("--- 分割线 ---");

        // 3. 创建【加载器 B】
        ClassLoader loaderB = new URLClassLoader(new URL[]{url}, null);
        Class<?> classB = loaderB.loadClass("MyTest");
        // 再次触发初始化
        classB.newInstance(); 
        
        // 4. 验证它们是不是同一个类
        System.out.println("classA == classB ? " + (classA == classB));
    }
}
```

我们使用了两个不同的ClassLoader对象强制触发了类加载。其实这个技术叫`热部署`，它会用在一些需要调试的场景，比如使用Springboot开发时，一修改后端就要重启着实司马，但是伟大的Spring Boot DevTools和Tomcat就会解决这个问题，它们内部就使用了这个机制。

接着我们看看第二条，为什么故意强调了非final呢？如果是一个`static final`的变量，实际上这就是个常量。

```java
class Constant {
    static final String MSG = "Hello";
    static { System.out.println("Static Block"); }
}

// 调用代码：
System.out.println(Constant.MSG);
```
这样做不会触发类加载，因为 `MSG` 是常量，编译器在编译阶段就把它偷偷“宏替换”到了 `Main` 类的常量池里。运行时 `Main` 类其实根本没理会 `Constant` 类。

然后我们看最傻逼的，`通过子类引用父类的静态变量`。

```java
class Super { 
    static int value = 123; 
    static { System.out.println("Super Init"); } 
}
class Sub extends Super { 
    static { System.out.println("Sub Init"); } 
}

// 调用代码：
System.out.println(Sub.value);
```
为什么这样做不会触发子类的类加载呢？实际上这叫做`懒加载`，虽然一个智力正常的人类会直接写`Super.value`，但是你用子类去这样写没任何问题。编译器非常聪明地看到实际上你根本没用子类的任何东西，也就无需加载子类了。

然后是定义数组引用：

```java
Student[] students = new Student[10];
```
这当然不会触发类加载，因为压根就没建对象，里面都是null，其他的什么ArrayList也是一样的道理。

其实最容易混淆的就是`成员变量`这里，因为静态的我们都清楚它是和类直接绑定的，所以我们只看左边就行，但是成员变量竟然也是静态绑定的。

所以`Java的多态，是非静态方法的多态`

看一个纯唐例子：

```java
class Baap {
    public int h = 4;

    public int getH() {
        System.out.println("Baap " + h);
        return h;
    }
}

public class Beta extends Baap {
    public int h = 44;

    @Override
    public int getH() {
        System.out.println("Beta " + h);
        return h;
    }

    public static void main(String[] args) {
        Baap b = new Beta();
        System.out.println(b.h + " " + b.getH());
        Beta bb = (Beta) b;
        System.out.println(bb.h + " " + bb.getH());
    }
}
```

首先`b` 声明类型为 Baap，实际对象为 Beta，那访问属性看左边但调用方法看右边，所以`b.getH()`的返回值就是Beta类内部的h的值，就是44

```
Beta 44 
4 44 
```

接着他强转了类型，换言之声明类型为 Beta，实际对象为 Beta，那这就好办了

```
Beta 44 
44 44
```

这个例子就很好说明了刚才表格写的。

接着我们来看一个例子：

```java
class Super {
    public int num = 10;
    public void run() { System.out.println("Super Run"); }
    public static void fly() { System.out.println("Super Fly"); }
}

class Sub extends Super {
    public int num = 20;
    public void run() { System.out.println("Sub Run"); }
    public static void fly() { System.out.println("Sub Fly"); }
}

public class Exam {
    public static void main(String[] args) {
        Super s = new Sub(); // 【核心】左边 Super，右边 Sub
        
        
        System.out.println(s.num); 
        s.run();
        // !!
        s.fly();
    }
}
```

我们试图用对象调用一个静态方法，虽然这是一种脑瘫写法，因为这等价于`Super.fly()`，但是我们还是要说一句：`静态方法是不参与多态的`。

最后是关于`重载 (Overloading) 的绑定时机`，这个容易出错：

```java
class Tester {

    void test(Dog d)    { System.out.println("测试狗"); }
}

Animal a = new Dog(); // 左边 Animal，右边 Dog
Tester t = new Tester();

t.test(a);
```

必须强调，`重载是静态绑定`。那么就根据之前那个表格我们就知道了，看左边。

test(a)尽管对象是Dog类，但是声明是Animal类的，所以参数类型就是Animal类型，输出必然是：

```
测试动物！
```

总结一下：

在做 OOA 题目时，看到 Parent p = new Child();，脑子里立刻要浮现出三行字：

- 方法调用： 它是谁？(看 new 出来的对象)

- 变量访问： 它的引用类型是什么？(看定义的类型)

- 静态方法： 它的引用类型是什么？(看定义的类型)

只有普通方法是“特立独行”的，其他全是看引用类型。

## 重写三定律 (Overriding Rules)

重写就是子类试图修改父类里已经存在的方法，当你看到打上@Override注解的时候，多半就是这种情况了。

### 定律一：三同 (Signature & Return) —— 身份核查

这里得介绍重载(Overload)的概念，重载其实就是一个类内部的同名但是参数列表不相同的几个方法之间形成的关系，这非常常见，比如构造方法的重载。

- 方法名相同。

- 参数列表相同（类型、个数、顺序完全一样）。

⚠️ 陷阱： 如果参数列表变了一点点（比如 int 变 long），那就不是重写了，那是重载！那是两个无关的方法。

- 返回类型相同（或更小） —— Covariant Return Type (协变返回类型)。

Java 5 之前的古板规则： 必须完全一模一样。

现在的规则： `子类方法的返回值，可以是父类返回值的子类。`

```java
class Parent {
    // 父类返回 Number
    Number getValue() { return 10; }
}

class Child extends Parent {
    // ✅ 正确！Integer 是 Number 的子类 (更小/更具体)
    @Override
    Integer getValue() { return 20; }

    // ❌ 错误！Object 是 Number 的父类 (太大/太宽泛)
    // @Override
    // Object getValue() { return "Error"; } 
}
```
### 定律二：两小 (Exceptions) —— 风险控制

这个是经常注意不到的：

- 抛出的 Checked Exception 范围变小（或相同）。

子类可以抛出父类异常的子类。

子类可以不抛出任何异常。

❌ 绝对不能抛出父类没声明的、更宽泛的 Checked Exception。

- 抛出的 Checked Exception 个数变少。

⚠️ 核心特例（考试必考）：RuntimeException 不受限制！

如果是 NullPointerException, IllegalArgumentException 这种运行时异常，子类爱怎么抛怎么抛，编译器根本不管。

规则只限制 Checked Exception (如 IOException, SQLException)。

```java
class Parent {
    void work() throws IOException { } // 声明会有 IO 风险
}

class Child extends Parent {
    // ✅ 情况1：抛出子异常 (FileNotFound 是 IO 的子类)
    @Override
    void work() throws FileNotFoundException { }

    // ✅ 情况2：什么都不抛 (我很安全)
    @Override
    void work() { }

    // ✅ 情况3：抛出运行时异常 (编译器不管)
    @Override
    void work() throws NullPointerException { }

    // ❌ 情况4：抛出更大异常 (Exception 是 IO 的父类) -> 编译错误！
    // @Override
    // void work() throws Exception { }
}
```

你可能觉得，为啥要子类抛的异常要是父类异常的子类？子类弄个更大的异常兜底不好吗？

因为要满足Liskov 替换原则 (Liskov Substitution Principle, LSP) 是面向对象设计原则 (SOLID) 中最重要、也最容易被误解的一个。

简单用一句话概括就是： “凡是父类对象出现的地方，都能用子类对象替换，而且程序不会出错。”

听起来像是废话？但实际上，Java 的重写规则（三同、两小、一大）全都是为了维护这个原则而存在的。

假设你用更大的异常兜底，那么想想看，父类出现的地方还能不能用子类出现？

### 定律三：一大 (Access Modifiers) —— 门户开放

保证“父类能去的地方，子类也能去”。

- 访问权限必须变大（或相同）。排序： public > protected > package-private (默认) > private。

如果父类是 protected，子类只能是 protected 或 public。如果父类是 public，子类只能是 public（不能退步）。

💀 接口实现的终极陷阱：

这也是我们刚才聊过的：

接口方法： 默认是 public abstract。实现类： 必须显式加上 public。如果你忘了写修饰符，它就变成了 package-private，权限变小了 $\rightarrow$ 编译错误。

```java
class Parent {
    protected void sleep() { }
}

class Child extends Parent {
    // ✅ 变大 (Public > Protected)
    @Override
    public void sleep() { }

    // ❌ 变小 (Default < Protected)
    // @Override
    // void sleep() { } 
}
```
所以咱们总结一下：

final 方法： 官方禁止修改。

static 方法： 属于类，不属于对象。（子类同名方法叫“隐藏”）。

private 方法： 子类根本看不见，无法重写。（子类同名方法是“新定义的方法”）。

这里这个Default，也就是缺省我们需要注意：

```java
class Person {
    String name; // 没写 public，也没写 private -> 这就是 Default 权限
    
    void run() { } // 同上
}
```

如果是一般的实例方法，缺省其实就是package-private，就是我们最熟悉的那个Default权限。

```java
interface Runner {
    // 这里的 default 不是权限！它代表“默认实现”！
    default void run() { 
        System.out.println("跑");
    }

    void stop();
}
```
默认方法不写权限，默认它是public的。而普通的接口内部的方法，是public abstract的

所以我们刚才为什么提这个接口的权限问题，看下面这个：

```java
// 1. 定义接口
interface Animal {
    void eat(); 
}

// 2. 实现类
class Dog implements Animal {
    
    void eat() { 
        System.out.println("狗吃肉");
    }
}
```

接口内部必然是public的，但是你实现的方法居然是default，也就是package-private的，这样就会报错。

## 抽象与接口的博弈 (Abstract vs Interface)

我们必须先理解他俩的区别。

抽象类，只不过就是一个无法直接实例化的类，他必须通过其他类的继承去实现内部的`抽象方法`，神奇的是`它有构造方法`，因为这是给他子类提供的。

但是你懂的，囿于他类的身份限制，子类只能继承他一个，他自己也只能有一个父类，这就意味着扩展性没接口好。最重要的`可以有实例变量和实例方法`。

接口是个神奇的东西，它无法实例化，也没构造方法，更没成员变量。他支持多实现，一旦一个类实现某个接口，就必须实现接口内部所有的抽象方法。

如果内部有变量声明，那它一定是个常量（static final）的。Java 9在接口里增加了`默认方法`，下面会说到。
