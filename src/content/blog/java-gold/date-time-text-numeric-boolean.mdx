# 常见问题

## 数值、包装类与运算

### 数值提升 (Numeric Promotion) —— 强制类型转换以及隐式转换

#### 先看强制类型转换。

先来看看每个类型的字节数：byte short int long float double boolean char (12484812)
一般来说，强制类型转换发生在大范围向小范围数据转化的情况：
1. 小数转整数
   当把 double 或 float 强转为 long 或 int 时。
   一般会造成精度丢失。
```java
double d1 = 9.9999;
int i1 = (int) d1; 
System.out.println(i1); // 输出 9 (不是10！)

double d2 = -9.9999;
int i2 = (int) d2;
System.out.println(i2); // 输出 -9
```
2. 大整数转小整数

当把 int 强转为 byte、short 时，或者 long 转 int 时。这是最难理解的，因为它涉及 二进制截断。

规则： 内存就像一把剪刀，直接剪掉多余的高位 (High-order bits)，只保留低位。

造成溢出会导致错误结果：
```java
int x = 128;
byte b = (byte) x;
System.out.println(b); // 输出 -128 

int y = 256;
// 256 二进制是 ... 1 00000000
// 剪掉前面，只剩 8 个 0
byte b2 = (byte) y;
System.out.println(b2); // 输出 0 
```
3. 字符与数字的互转
   这个是最出生的，char和short类型的互转。
   char 是 无符号 的 16 位整数 (0 ~ 65535)。 short 是 有符号 的 16 位整数 (-32768 ~ 32767)。
   他们都是2字节，但是范围不一样，所以这对是唯一一个数据大小一样但互转时都需要强转的。

数字转字符：高位截断，剩下当ascii处理

字符转数字：正常按强转规则就行，唯一注意的就是short。

4. boolean禁止强转


#### 再看隐式转换

一般出现在运算中的，都是隐式转换：
- 一元运算 (-, ~)： byte/short/char 变 int。
- 二元运算 (+, *...)： 有 double 变 double，没 double 有 float 变 float，没 float 有 long 变 long。全都没有？统统变 int。
- 自增运算 (++)： 自带强转，不改变类型。
- 三元运算 (? :)： 哪怕只选中了 int，只要另一边是 double，结果就是 double。
- Long $\rightarrow$ Float： 编译不报错，运行丢精度。

一个一个看例子。

首先是一元运算：

byte/short/char 遇到 +, -, ~ 会发生什么？我们举个最极端的例子

```java
public void test1() {
    short s = 10;
    
    // 问：下面这行代码能编译通过吗？
    // 逻辑：把 s 变成正数（虽然它本来就是正的），再赋值回去
    s = +s; 
    
    System.out.println(s);
}
```

这就会编译错误，因为即便你没改值，也仍然会转换成int类型，这时候赋值就会出错。

二元运算：
```java
public void test1() {
    short s = 10;
    
    // 问：下面这行代码能编译通过吗？
    s = 1 + s; 
    
    System.out.println(s);
}
```
仍然不行，直接写的这种整数都是int，这里就会转成int类型。

三元运算符：
```java
public void test2() {
    int count = 5;
    
    // 问：result 的实际类型是什么？打印出来是 5 还是 5.0？
    var result = (count > 0) ? count : 99.9;
    
    System.out.println(result);
}
```

向最高的数据类型看齐，这个情况result就是double类型。顺带一提，直接写的这种小数都是double类型，不是float，这要注意。

自增运算：
```java
public void test1() {
    short s = 10;
    
    // 问：下面这行代码能编译通过吗？
    s = s++; 
    
    System.out.println(s);
}
```
这里就可以，因为自增运算不改变类型。

### 包装类

这里的包装类是指：Integer Character	Byte Short Long Float Double Boolean。
他们是对基本类型的封装。因为泛型歧视基本类型，所以比如当我们想用集合存基本类型，那就不得不用包装类。

#### 自动装箱与拆箱

装箱 (Boxing)： 基本类型 $\rightarrow$ 包装类。

代码：Integer a = 10;

真相：编译器替换为 Integer a = Integer.valueOf(10);

拆箱 (Unboxing)： 包装类 $\rightarrow$ 基本类型。

代码：int b = a;

真相：编译器替换为 int b = a.intValue();

问题在于，什么时候会自动发生？

- 集合操作，存基本数据类型自动装箱
- 包装类参与四则运算自动拆箱
- 当包装类和基本类型用 == 比较时自动拆箱

#### 缓存池 (The Cache Pool)

Java会把一些常用的数值存在缓存池里。

缓存范围：

- Byte, Short, Integer, Long：-128 到 127

- Character：0 到 127

- Boolean：true 和 false 都有缓存。

- Float 和 Double 没有缓存

另外要注意的：== 是比较地址而.equals() 比较的是数值。

所以：

```java
Integer i1 = 100;
Integer i2 = 100;
System.out.println(i1 == i2);      // ✅ true (命中缓存)

Integer i3 = 200;
Integer i4 = 200;
System.out.println(i3 == i4);      // ❌ false (超出范围，new 了新对象)

Double d1 = 10.0;
Double d2 = 10.0;
System.out.println(d1 == d2);      // ❌ false (浮点数没有缓存)

Boolean b1 = true;
Boolean b2 = true;
System.out.println(b1 == b2);      // ✅ true (Boolean 只有俩值，肯定缓存)
```

#### 不可变性

所有的包装类对象都是不可变的。这意味着，你一旦创建了一个 Integer i = 10;，这个对象里的 10 永远不会变成 11。

那它是如何做到增加它的值的，比如：

```java
public void modify(Integer x) {
    x = x + 1; // 这里 x 指向了一个新对象
}

public static void main(String[] args) {
    Integer i = 10;
    modify(i);
    System.out.println(i); // 输出还是 10！
    // 因为 Integer 是传递引用的副本，且 Integer 本身不可变。
}
```

所以它创建了一个新对象去代替了原对象。
