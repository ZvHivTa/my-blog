# 常见问题

## 数值、包装类与运算

### 数值提升 (Numeric Promotion) —— 强制类型转换以及隐式转换

#### 先看强制类型转换。

先来看看每个类型的字节数：byte short int long float double boolean char (12484812)
一般来说，强制类型转换发生在大范围向小范围数据转化的情况：
1. 小数转整数
   当把 double 或 float 强转为 long 或 int 时。
   一般会造成精度丢失。
```java
double d1 = 9.9999;
int i1 = (int) d1; 
System.out.println(i1); // 输出 9 (不是10！)

double d2 = -9.9999;
int i2 = (int) d2;
System.out.println(i2); // 输出 -9
```
2. 大整数转小整数

当把 int 强转为 byte、short 时，或者 long 转 int 时。这是最难理解的，因为它涉及 二进制截断。

规则： 内存就像一把剪刀，直接剪掉多余的高位 (High-order bits)，只保留低位。

造成溢出会导致错误结果：
```java
int x = 128;
byte b = (byte) x;
System.out.println(b); // 输出 -128 

int y = 256;
// 256 二进制是 ... 1 00000000
// 剪掉前面，只剩 8 个 0
byte b2 = (byte) y;
System.out.println(b2); // 输出 0 
```
3. 字符与数字的互转
   这个是最出生的，char和short类型的互转。
   char 是 无符号 的 16 位整数 (0 ~ 65535)。 short 是 有符号 的 16 位整数 (-32768 ~ 32767)。
   他们都是2字节，但是范围不一样，所以这对是唯一一个数据大小一样但互转时都需要强转的。

数字转字符：高位截断，剩下当ascii处理

字符转数字：正常按强转规则就行，唯一注意的就是short。

4. boolean禁止强转


#### 再看隐式转换

一般出现在运算中的，都是隐式转换：
- 一元运算 (-, ~)： byte/short/char 变 int。
- 二元运算 (+, *...)： 有 double 变 double，没 double 有 float 变 float，没 float 有 long 变 long。全都没有？统统变 int。
- 自增运算 (++)： 自带强转，不改变类型。
- 三元运算 (? :)： 哪怕只选中了 int，只要另一边是 double，结果就是 double。
- Long $\rightarrow$ Float： 编译不报错，运行丢精度。

一个一个看例子。

首先是一元运算：

byte/short/char 遇到 +, -, ~ 会发生什么？我们举个最极端的例子

```java
public void test1() {
    short s = 10;
    
    // 问：下面这行代码能编译通过吗？
    // 逻辑：把 s 变成正数（虽然它本来就是正的），再赋值回去
    s = +s; 
    
    System.out.println(s);
}
```

这就会编译错误，因为即便你没改值，也仍然会转换成int类型，这时候赋值就会出错。

二元运算：
```java
public void test1() {
    short s = 10;
    
    // 问：下面这行代码能编译通过吗？
    s = 1 + s; 
    
    System.out.println(s);
}
```
仍然不行，直接写的这种整数都是int，这里就会转成int类型。

三元运算符：
```java
public void test2() {
    int count = 5;
    
    // 问：result 的实际类型是什么？打印出来是 5 还是 5.0？
    var result = (count > 0) ? count : 99.9;
    
    System.out.println(result);
}
```

向最高的数据类型看齐，这个情况result就是double类型。顺带一提，直接写的这种小数都是double类型，不是float，这要注意。

自增运算：
```java
public void test1() {
    short s = 10;
    
    // 问：下面这行代码能编译通过吗？
    s = s++; 
    
    System.out.println(s);
}
```
这里就可以，因为自增运算不改变类型。

### 包装类

这里的包装类是指：Integer Character	Byte Short Long Float Double Boolean。
他们是对基本类型的封装。因为泛型歧视基本类型，所以比如当我们想用集合存基本类型，那就不得不用包装类。

#### 自动装箱与拆箱

装箱 (Boxing)： 基本类型 $\rightarrow$ 包装类。

代码：Integer a = 10;

真相：编译器替换为 Integer a = Integer.valueOf(10);

拆箱 (Unboxing)： 包装类 $\rightarrow$ 基本类型。

代码：int b = a;

真相：编译器替换为 int b = a.intValue();

问题在于，什么时候会自动发生？

- 集合操作，存基本数据类型自动装箱
- 包装类参与四则运算自动拆箱
- 当包装类和基本类型用 == 比较时自动拆箱

#### 缓存池 (The Cache Pool)

Java会把一些常用的数值存在缓存池里。

缓存范围：

- Byte, Short, Integer, Long：-128 到 127

- Character：0 到 127

- Boolean：true 和 false 都有缓存。

- Float 和 Double 没有缓存

另外要注意的：== 是比较地址而.equals() 比较的是数值。

所以：

```java
Integer i1 = 100;
Integer i2 = 100;
System.out.println(i1 == i2);      // ✅ true (命中缓存)

Integer i3 = 200;
Integer i4 = 200;
System.out.println(i3 == i4);      // ❌ false (超出范围，new 了新对象)

Double d1 = 10.0;
Double d2 = 10.0;
System.out.println(d1 == d2);      // ❌ false (浮点数没有缓存)

Boolean b1 = true;
Boolean b2 = true;
System.out.println(b1 == b2);      // ✅ true (Boolean 只有俩值，肯定缓存)
```

#### 不可变性

所有的包装类对象都是不可变的。这意味着，你一旦创建了一个 Integer i = 10;，这个对象里的 10 永远不会变成 11。

那它是如何做到增加它的值的，比如：

```java
public void modify(Integer x) {
    x = x + 1; // 这里 x 指向了一个新对象
}

public static void main(String[] args) {
    Integer i = 10;
    modify(i);
    System.out.println(i); // 输出还是 10！
    // 因为 Integer 是传递引用的副本，且 Integer 本身不可变。
}
```

所以它创建了一个新对象去代替了原对象。

#### 其他小坑

Boolean的解析
```java
System.out.println(Boolean.parseBoolean("True"));   // true
System.out.println(Boolean.parseBoolean("yes"));    // false
System.out.println(Boolean.parseBoolean("1"));      // false
System.out.println(Boolean.parseBoolean(null));     // false (不死机)
```

换言之除了true以外的字符串装箱到Boolean类里是不会出问题的，都是false。



### Math API

#### ceil, floor, round

这几个其实就是数学上的向上、向下取整和四舍五入，我们只需记得这几个规律：

- ceil (天花板/向上): 往 正无穷大 (+∞) 方向找最近的整数。

- floor (地板/向下): 往 负无穷大 (-∞) 方向找最近的整数。

- round (四舍五入): 算法是 (long) Math.floor(x + 0.5d)。

这里最讨厌的是他们的返回值类型。

- 规则 A: ceil() 和 floor() 返回的是 double！哪怕结果看起来是个整数。

- 规则 B: round() 返回的是 long (如果是 float 参数则返回 int)。


另外的一些`abs`函数、`random`函数，就没什么特殊的了。

## 文本处理 (String & StringBuilder)

### String

String类内部有些方法是要重新赋值的，所以要注意区别现在流行的链式调用：

```java
String s = "Java";
s.concat(" Exam"); // 创建了一个新对象 "Java Exam"，但没人接收它！
s.toUpperCase();   // 创建了一个新对象 "JAVA"，也没人接收！

System.out.println(s); 
// 结果还是 "Java"！(s 根本没变)
```

另外比较重要的：`String Constant Pool (字符串常量池)`

就两条规则：

- 字面量 (" ")： 会放入常量池。如果池子里有，直接复用。

- new String()： 强制在堆内存 (Heap) 创建新对象，不走常量池。

比如：
```java
String s1 = "Hello";
String s2 = "Hello";
System.out.println(s1 == s2); // ✅ true (同一个池子里的引用)

String s3 = new String("Hello");
System.out.println(s1 == s3); // ❌ false (s3 是堆里的新地盘)
```
另外一些常用的String类方法记忆一下就可以了，一般都和方法名能联系上。

### StringBuilder

StringBuilder 是为了修改而生的。 它的操作大多是 原地修改 (In-place)，不会创建新对象。这也就是我们提到的链式调用的形式。

```java
StringBuilder sb = new StringBuilder("Java");
sb.append(" 17").delete(0, 4).insert(0, "OCP");

System.out.println(sb); 
// 1. append -> "Java 17"
// 2. delete(0,4) -> " 17" (删掉 Java)
// 3. insert -> "OCP 17"
```
无限连着写，不建新对象。

注意：StringBuilder 没有重写 equals，它比较的就是地址。而String重写了equals，所以比较的是内容。

然后我们看比较头痛的：索引与切片

不管是 String 还是 StringBuilder，只要涉及 范围 (Range) 的方法（substring, delete, replace），都遵循 Java 的 “含头不含尾” 黄金法则。

法则：[startIndex, endIndex)

包含 startIndex

不包含 endIndex

🧠 快速计算长度公式： Length = endIndex - startIndex

### 文本块 (Text Blocks) —— Java 15+

首先看它的形式：

```java
// ❌ 编译错误
String s = """Hello"""; 

// ✅ 正确
String s = """
           Hello
           """;
```
""" 后面必须有个换行符，不然就会出错。

接下来必须看看它的规则，随便给你一个带各种缩进的文本块，怎么知道它到底是空格还是咋的呢？

编译器非常聪明，它会自动去除“多余的缩进”，也就是偶然空白 (Incidental Whitespace)。 

怎么算多余？ 画一条竖线，以每一行（包括结束的 """）中最左侧的非空字符为基准。

例如：
```java
String html = """
              <html>
                  <body></body>
              </html>
              """; 
// 问：<html> 前面有几个空格？
```
html标签前是没有空格的，因为和起始引号对齐了，body标签前面有4个空格。

还有：
```java
String s = """
           line1
           line2
       """; // 注意！结束符 """ 向左缩进了！
```

下面的结束符向左缩进，那就取起始符和结束符中间最靠左的，所以这个字符串就是`   line1   line2`

### StringBuffer

StringBuffer 就是线程安全的 StringBuilder。似乎前者比后者好，但是事实上，这个线程安全的家伙是鼻祖，因为其实现实业务中，大部分修改字符串的操作都在一个线程里进行，就没什么必要特意用这个效率差的类了。

这两个类的方法完全一致。



## 日期与时间 (Date-Time API)

旧时代，Java处理日期时间的包是java.util.Date 和 Calendar，这两个类由于线程不安全+设计垃圾已经被彻底地淘汰。所以见到问线程安全的时间处理包，一旦看到`util`这个包出现了，那它就是错的。

现在我们一般用Java8出品的`java.time` 包，它是通过不可变性+线程安全来维护时间API的。

1. 不可变性：当你想在一个时间对象上进行比如+1天的操作时，是不会在原对象上操作的。它每次都会产生一个新对象，所以我们无法通过链式调用的形式去操作他们。

我们随便举个例子：

```java title="java.time.LocalDateTime 中的"
    /**
     * Returns a copy of this date-time with the new date and time, checking
     * to see if a new object is in fact required.
     *
     * @param newDate  the date of the new date-time, not null
     * @param newTime  the time of the new date-time, not null
     * @return the date-time, not null
     */

    private LocalDateTime with(LocalDate newDate, LocalTime newTime) {
        if (date == newDate && time == newTime) {
            return this;
        }
        return new LocalDateTime(newDate, newTime);
    }
```
LocalDateTime中的操作，基本所有的代码都是这样，返回了一个新对象。with这个方法就是一个组装LocalDate和LocalTime的功能，而其他的操作，比如plus，minus都基于这个方法。

2. 线程安全：正是由于它的不可变性，所以它们在多线程环境下是绝对安全的。

我们分几个层次介绍内部常用的时间类：

1. 只有“数值”，没有“时区” (Local 系列)
2. 加上“定位”，变成绝对时间 (Zoned & Instant)
3. 时间的“长度” (Amount)
4. 工具类 (Formatter & Adjuster)
   
### Local 系列

1. LocalDate (只看日子)

包含： 年、月、日。

场景： 生日、入职日期、法定节假日。

代码： LocalDate.of(2023, 10, 1)

2. LocalTime (只看表)

包含： 时、分、秒、纳秒。

场景： 每天的午休时间（12:00）、商店开门时间。

代码： LocalTime.of(13, 30)

3. LocalDateTime (日子+表)

包含： 年月日 + 时分秒。

本质： LocalDate + LocalTime。

场景： 记录在这个系统内部发生的事件（比如“订单创建时间”）。

代码： LocalDateTime.now() 这是最常用的返回当前时间的代码。

这三个类不代表绝对时间点。 比如 LocalDateTime 记下的 2023-01-01 00:00，在纽约是那一刻，在东京是另一刻。它们只是由数字组成的符号，与真实地点的时间没有关系。

### Zoned & Instant

如果你要搞跨国会议，或者记录服务器日志（要求全球统一），就需要这一层。

1. ZoneId (时区 ID)

这是时区的身份证。

常见值： "Asia/Shanghai", "America/New_York", "UTC"。

2. ZonedDateTime (带时区的完整时间)

公式： LocalDateTime + ZoneId = ZonedDateTime

含义： “2023年1月1日 10:00 的 上海时间”。这是一个宇宙中唯一确定的时刻了。

转换： 当你把一个 Local 时间附加上 ZoneId，它就变成了 Zoned 时间。

3. Instant (时间戳/机器时间)

含义： 从 1970-01-01 00:00:00 UTC 开始算起的秒数（纳秒精度）。

场景： 也是宇宙绝对时间，主要给 计算机/数据库 看的。

关系： ZonedDateTime 转化成 Instant 就是同一个时刻，只是表达方式不同（一个是人读的，一个是机器读的）。

所以：

- LocalDateTime = LocalDate + LocalTime

- ZonedDateTime = LocalDateTime + ZoneId

这些常用的时间类，基本都是通过静态工厂方法创建的对象，所以你不能new他们，因为他们的构造方法都是private的。

### 时间的“长度”

这一层专门用来计算 “两个时间点之间隔了多久”。这里最容易混淆，请严格区分 物理时间 和 日历时间。

1. Duration (基于物理秒)

单位： 天(Days)、时(Hours)、分、秒、纳秒。

用途： 它是基于 LocalTime 或 Instant 的。

特征： 极其精准。1天永远等于24小时（86400秒）。

场景： “任务执行了多久”、“倒计时”。

2. Period (基于日历)

单位： 年(Years)、月(Months)、日(Days)。

用途： 它是基于 LocalDate 的。

特征： 不精准（符合人类直觉）。“1个月”可能是28天，也可能是31天；“1天”如果遇到夏令时切换，可能是23小时或25小时。

场景： “距离退休还有多少年”、“如果你只存了年月日，就必须用这个”。

所以你只需记住：

- Duration和LocalTime搭配使用
- Period和LocalDate搭配使用
- LocalDateTime这两个都能使

### DateTimeFormatter 和 TemporalAdjusters

1. DateTimeFormatter (格式化器)
   
它主要用来实现字符串和时间类互转。它是线程安全的（再次强调，以前的 SimpleDateFormat 是不安全的）。

常用的：

- DateTimeFormatter.ISO_LOCAL_DATE ，或者自定义 ofPattern("yyyy-MM-dd")。
- format(): 对象 $\rightarrow$ 字符串
- parse(): 字符串 $\rightarrow$ 对象

```java
LocalDateTime dt = LocalDateTime.now();
DateTimeFormatter f = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm");

// 1. 变成字符串
String s = dt.format(f); 
// 或者反过来写（效果一样，推荐这种）：
String s2 = f.format(dt);

// 2. 变成对象
LocalDateTime dt2 = LocalDateTime.parse("2023-10-01 12:00", f);
```

2. TemporalAdjusters(时间校正器)
   
用于进行复杂的日期计算。比如，“下个月的第一个周五”、“本月的最后一天”。

```java
LocalDate today = LocalDate.now();
// 甚至读起来像英语一样通顺：
LocalDate nextFri = today.with(TemporalAdjusters.next(DayOfWeek.FRIDAY));
```

### 夏令时

那么到此为止，似乎ZonedDateTime和LocalDateTime没啥区别，这就牵扯出最阴险的考点：夏令时（Daylight Saving Time, DST）

在考试中，你不需要背诵哪个国家几月几号切夏令时（题目会告诉你，通常用美国的规则：3月开始，11月结束），但你必须知道 Java 是如何处理这两个特殊时刻的。

1. 春季：时间消失 (Spring Forward) —— "The Gap"
   
场景： 春天到了，我们需要把表 拨快 1 小时。 比如：凌晨 1:59:59 过了之后，直接跳到 3:00:00。 意味着： 2:00 到 2:59 这一个小时的时间在当地根本不存在！

考题模拟：如果你非要创建一个“不存在的时间”，Java 会怎么办？

```java
// 假设：2023年3月12日凌晨2点切换夏令时（2点不存在了）
ZoneId usZone = ZoneId.of("America/New_York");

// 你的代码非要创建 2023-03-12 02:30 这个不存在的时间
ZonedDateTime zdt = ZonedDateTime.of(
    LocalDate.of(2023, 3, 12), 
    LocalTime.of(2, 30), // 👈 搞事情，这时候正好是真空期
    usZone
);

System.out.println(zdt);
```
不会报错！ Java 很聪明（也很鸡贼）。

结果： 2023-03-12T03:30-04:00[America/New_York]

Java 的策略： 既然 2:30 不存在，我就顺延那个偏移量（+1小时）。你以为是 2:30，实际变成了 3:30。

2. 秋季：时间重叠 (Fall Back) —— "The Overlap"
   
场景： 秋天到了，我们需要把表 拨慢 1 小时。 比如：到了凌晨 2:00，突然时光倒流，变回了 1:00。 意味着： 1:00 到 1:59 这一个小时，这一天经历了两次！

考题模拟：如果你创建 1:30，Java 怎么知道是“第一次的1:30”还是“第二次的1:30”？

```java
// 假设：2023年11月5日凌晨2点结束夏令时（时间倒流回1点）
ZoneId usZone = ZoneId.of("America/New_York");

// 创建 1:30
ZonedDateTime zdt = ZonedDateTime.of(
    LocalDate.of(2023, 11, 5), 
    LocalTime.of(1, 30), 
    usZone
);

System.out.println(zdt);
```

仍然不会报错！

默认策略： Java 会选择 早 的那个时间（也就是切换前的那个偏移量）。

结果： 2023-11-05T01:30-04:00 (夏令时还在生效时的 1:30)。

如果你非要那个“第二次的 1:30”，你需要用 withLaterOffsetAtOverlap() 方法。

3. 最出生的：Period vs Duration 在夏令时的表现
   
这是考夏令时最阴间的一道题。

问： 过了 1 天，到底意味着什么？是“日历翻了一页”，还是“过了24小时”？

假设 3月12日 是夏令时切换日（这一天只有 23 小时）。

Period (周期) 的逻辑： 我只看日历，不管物理时间。

Duration (时长) 的逻辑： 我是物理时间，我必须过满 24 个小时（3600秒 * 24）。

```java
ZoneId zone = ZoneId.of("America/New_York");
// 3月12日 10:00 (切换日)
ZonedDateTime start = ZonedDateTime.of(2023, 3, 12, 10, 0, 0, 0, zone);

// 方式 A：加 Period (1天)
ZonedDateTime resultA = start.plus(Period.ofDays(1));

// 方式 B：加 Duration (24小时)
ZonedDateTime resultB = start.plus(Duration.ofHours(24));

System.out.println(resultA); // ?
System.out.println(resultB); // ?
```
resultA (Period): 2023-03-13T10:00

resultB (Duration): 2023-03-13T11:00

所以一般处理夏令时要用Period，因为它不像Duration精确。Period 只是把日历从 12号 改成了 13号，并保留原本的时间（10:00）。符合人类直觉。而如果使用Duration，它只关注小时层面的东西，所以它会造成错误。
